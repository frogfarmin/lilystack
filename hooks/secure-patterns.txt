# lilystack secure rules. Rewritten from claude-plugins-official plugins/security-guidance/hooks/patterns.py
# and security_reminder_hook.py at a1ecfbc (Apache-2.0, Copyright Anthropic, PBC; changed): the rules are
# POSIX ERE instead of Python regex, the reasons are shortened, the gh-workflow rule checks the text
# instead of every workflow edit, and the session state, telemetry and model review are left out.
#
# One per line: warn<TAB>name<TAB>path<TAB>reason<TAB>regex[<TAB>unless-regex].
#   path    which files the rule applies to: * (any file), an ERE the file path must match, or !ERE
#           (the path must not match). Paths match case-insensitively.
#   regex   POSIX ERE, case-sensitive, matched against each line of the new text only.
#   unless  a line that also matches it does not count.
# A rule that also matches the old text (Edit and MultiEdit old_string; for Write and NotebookEdit, the
# file already on disk) is skipped: it was there before this edit. Every match is reported; nothing is
# blocked. Edit a line to change a rule; tests/test-hooks.zsh pins the behaviour.
#
# Gates used below: JS \.(js|jsx|ts|tsx|mjs|cjs|mts|cts|vue|svelte)$   PY \.(py|pyi|ipynb)$
#                   not docs !\.(md|mdx|txt|rst|json|ya?ml)$            not prose !\.(md|mdx|txt|rst)$
