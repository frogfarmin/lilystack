# the rows added on 2026-11-06 are new work, written from the behaviour of each tool.
# lilystack careful rules. One per line: tier<TAB>name<TAB>reason<TAB>regex[<TAB>unless-regex].
# Tiers: deny (blocked) or ask (a prompt). Each regex is POSIX ERE, matched case-insensitively (grep -E -i)
# against each line of the command. The first matching row wins, so deny rows come first and a row with
# a specific reason sits above the general one it overlaps. A match on unless-regex turns that row off;
# it is tested on the same pipe stage as the regex, with an unquoted # comment cut off, so neither
# `npm publish # --dry-run` nor `npm publish | grep -- --dry-run` turns the publish row off.
# Edit a line to change a rule; tests/test-hooks.zsh pins every row.
#
# Fragments repeated below (written out in full, because grep has no macros):
#   command position  ((^|[^[:alnum:]_.[:space:]-])[[:space:]]*|(^|[^[:alnum:]_.-])-?(sudo|...|eval)(...)*[[:space:]]+)
#                     start of a line, after punctuation (; & | ( ` " ' \ /), or after a prefix such as
#                     sudo, xargs, find -exec, env, then or do, or a wrapper such as caffeinate, stdbuf, flock or
#                     busybox (keep the list in step with the wrapper list in freeze.sh analyze); so git rm,
#                     npm rm and docker run --rm do not count
#   argument          [[:space:]]+[^[:space:];&|<>]+   one word that does not cross into the next command
#   git               git([[:space:]]+--?[a-z][a-z-]*(=...|[[:space:]]+value)?)*[[:space:]]+   also git -C dir
#
